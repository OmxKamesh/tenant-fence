# Security

Use synthetic data and explicitly authorized local/staging targets only. Do not submit customer data, access tokens, API keys or private report/config files in issues.

If you discover a vulnerability in Tenant Fence, use GitHub's private vulnerability reporting feature if enabled for the repository. If it is not enabled, open a minimal issue asking the maintainer for a private contact without publishing exploit details or secrets. Do not assume a response time or security support SLA.

A failing test of your own app belongs with that app's maintainers, not in this repository's public issues. A passing run is limited regression evidence, not certification.
